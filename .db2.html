For AI Agents

Hand your agent this brief or the ReUI MCP, not a screenshot. Installs with a ReUI Pro or Ultimate license.

Best for: Failed charges with the attempt history under each row, a Retry now that flips status to Retrying and a templated contact dialog

When to use

  • A back office for billing operators: the invoice ledger, subscriptions, a dunning queue and metered usage
  • Plan and discount admin: editing the plan catalog and coupon rules, or moving a subscription to a new tier
  • One customer's billing account seen by staff, or an invoice built line by line and then sent

When not to use

  • A full invoice ledger with bulk collector assignment and a void action: use the Invoice Ledger block
  • One customer's account with its invoices, payment methods and activity: use the Billing Account Detail block
  • A public page where visitors compare plan tiers and pick one before signing up: use the Pricing blocks
  • A signed in customer's own settings page showing their plan, usage and invoices: use the Profile blocks
  • A stepped intake flow with no money in it, such as vendor onboarding or team invites: use the Wizard blocks

Agent notes

  • getRecoveryStats reads the static PAST_DUE_INVOICES, so the stat strip does not move when Retry now changes a row
  • markRetrying only flips status to Retrying in state and never appends to attempts, so the attempt history does not grow
  • handleRetryAll, handleExport and handleRules in the header only toast; the grid's own handleRetryDue is what flips status
  • Each block sets a min-h-svh wrapper with bg-background, padding and a max width in page.tsx or its root component; drop it inside an app shell
  • No block calls an API: sends, retries, saves and exports update useState or fire a sonner toast; post to your billing backend from those handlers

  • TanStack Table v9: API reference, docs
  • Sonner v2: API reference, docs

Shadcn Dunning Queue Block

Expandable Dunning Queue for SaaS Failed Payment Recovery. Part of the ReUI Shadcn Solutions Billing blocks collection.

Sortable, filterable dunning queue for SaaS billing operators to recover failed charges. Expands inline to retry timeline. Features ReUI DataGrid, Frame, Filters; shadcn Button, Separator. Payment recovery, dunning list, failed billing.

It is composed from Avatar, Badge, Button, Data Grid, Dialog, Dropdown Menu, Field, Filters, and more, so every part of it is a primitive you can restyle with your own design tokens.

What You Can Build With the Dunning Queue Block

  • Install it with the ReUI registry command in the toolbar above, then swap the placeholder content, data wiring, and business logic for your own.
  • Compare it across all eight ReUI styles and both the Base UI and Radix bases in the customizer before committing to one direction.
  • Combine it with the other Shadcn Solutions Billing blocks to assemble a full screen instead of a single section.

Frequently Asked Questions

When should I use the Dunning Queue block?

Use it for failed charges with the attempt history under each row, a Retry now that flips status to Retrying and a templated contact dialog.

The Billing category fits:

  • A back office for billing operators: the invoice ledger, subscriptions, a dunning queue and metered usage
  • Plan and discount admin: editing the plan catalog and coupon rules, or moving a subscription to a new tier
  • One customer's billing account seen by staff, or an invoice built line by line and then sent

For a full invoice ledger with bulk collector assignment and a void action, use the Invoice Ledger block. For one customer's account with its invoices, payment methods and activity, use the Billing Account Detail block. For a public page where visitors compare plan tiers and pick one before signing up, use the Pricing blocks. For a signed in customer's own settings page showing their plan, usage and invoices, use the Profile blocks. For a stepped intake flow with no money in it, such as vendor onboarding or team invites, use the Wizard blocks.

What is the Dunning Queue block built with?

Dunning Queue uses Avatar, Badge, Button, Data Grid, Dialog, Dropdown Menu, Field, Filters, Frame, Item, Select, Separator, Spinner, Textarea. Installing the block through the ReUI registry pulls those dependencies in for you.

Can I restyle the Dunning Queue block?

Yes. It reads your design tokens, so switching style, radius, base color, font, or icon library in the customizer restyles it without touching the markup.

How should I use Shadcn billing blocks in a real project?

Treat them as structured starting points. Keep the layout, hierarchy, and interaction ideas that work, then replace placeholder content, data wiring, and business logic with your own product requirements.
